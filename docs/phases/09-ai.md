## Goal
Game AI: navmesh generation and A* pathfinding, steering with local
avoidance, behavior trees over a shared blackboard, and perception via
line-of-sight raycasts — ending with sandbox agents that patrol, navigate
around obstacles, spot the player, and give chase.

## Scope
- In scope: a grid-based navmesh baked from the level's static collision
  shapes (walkable cells from box footprints + agent radius inflation); A*
  over the grid (octile heuristic) with path smoothing (line-of-walkability
  shortcutting); steering (seek/arrive at path corners + separation from
  nearby agents); a hand-rolled behavior tree (Sequence/Selector/leaf
  actions/conditions, Running/Success/Failure ticks) reading and writing a
  blackboard (StringId → tagged-union value); perception — a vision cone +
  line-of-sight check through an *injected* raycast callback; sandbox demo
  agents (patrol → spot → chase → lose → return).
- Out of scope (deferred): Recast-style polygonized navmesh from arbitrary
  triangle soup (the grid bake covers box-built sandbox levels; revisit
  when levels stop being boxes); dynamic navmesh rebuild / carving for
  moving obstacles; hierarchical pathfinding (grid sizes here don't need
  it); velocity-obstacle avoidance (ORCA) — separation steering first;
  utility AI / GOAP / HTN planners; navigation links (jumps, ladders);
  crowd simulation at scale; any AI-side animation control (gameplay glue
  drives the Phase 6 state machine exactly as player input does).

## Module layout
New `engine/ai` module (`ge_ai`), **Layer 3 (Subsystems)**. Depends on
`ge_core` only — and critically **not** on `ge_physics` (sibling, golden
rule 1). Everything physical crosses the boundary as plain data or an
injected function:

- `include/ai/navgrid.h` + `src/navgrid.cpp` — `NavGrid`: origin, cell
  size, walkable bitmask; `bake_navgrid(const Box* statics, count, agent
  radius, arena)` rasterizes static box footprints (inflated by the agent
  radius) into blocked cells. Input is `ge_ai`'s own plain box struct
  (center/half-extents/yaw) so no physics type crosses.
- `include/ai/pathfind.h` + `src/pathfind.cpp` — A* over the grid: binary-
  heap open list, octile heuristic, preallocated per-query node scratch
  (arena); `smooth_path()` shortcuts corners via grid line-of-walkability
  (supercover line walk). Returns waypoints in world space.
- `include/ai/steering.h` + `src/steering.cpp` — pure functions:
  `seek/arrive(pos, vel, target, max_speed, slow_radius)` and
  `separation(pos, neighbors[], radius)` → desired velocity. The consumer
  feeds this to the physics capsule exactly like player input (physics
  stays the authority on motion, per the Phase 5/6 precedent).
- `include/ai/behavior_tree.h` + `src/behavior_tree.cpp` — `BtNode`
  (type enum + per-type payload, children as index ranges, arena-built,
  no virtuals per golden rule 4), `BtTree::tick(blackboard, dt)` →
  Running/Success/Failure with resume-from-running-child semantics;
  leaves are function pointers + user data (plain C++, ADR-0009).
- `include/ai/blackboard.h` — `Blackboard`: `HashMap<StringId, BbValue>`
  where `BbValue` is a tagged union (bool, f32, vec3, u32 entity bits).
- `include/ai/perception.h` + `src/perception.cpp` — vision test:
  distance + cone (dot vs cos half-angle) + `RaycastFn` line-of-sight
  callback (`bool (*)(void* user, vec3 from, vec3 to)`), injected by the
  app. Unit tests inject stubs; the sandbox injects a `PhysicsWorld`
  raycast wrapper.

**Sibling isolation.** `ge_ai` ↔ `ge_physics` meet only through (a) the
plain-box bake input, (b) the injected `RaycastFn`, and (c) the desired-
velocity output the sandbox feeds to the capsule — all app-mediated, same
shape as the `ge_anim`/`ge_gfx` palette contract. Requires `ge_physics` to
have a raycast query by then (Phase 5 shipped shape-vs-shape only) — a
ray-vs-broadphase + ray-vs-shape addition, listed as a dependency task in
Milestone 5, built in `ge_physics` where it belongs.

## Tech decisions
- **Grid navmesh, not polygonized.** Sandbox levels are boxes; a cell grid
  (0.25–0.5 m cells) inflated by agent radius is exact enough there and is
  two orders of magnitude simpler than Recast-style voxelize/region/
  contour/poly pipelines. The pathfind API speaks world-space waypoints,
  so a future polygon navmesh can replace the grid without touching
  consumers. Third-party note: vendoring Recast was considered and
  rejected for now — navigation *is* core AI, the from-scratch column.
- **A* with preallocated scratch** (open/closed/parent arrays sized to the
  grid, per-query arena reset) — zero allocation per query (ADR-0004).
- **Behavior trees over utility/GOAP:** the plan names BTs; they're
  debuggable (tick order is a unit test), data-oriented as flat node
  arrays, and cover patrol/chase/return cleanly.
- **Steering feeds physics, never writes transforms.** Same authority rule
  as Phases 5/6: AI outputs desired velocity; the capsule + solver decide
  what actually happens.
- **Fixed-timestep ticking** for BT + steering (same accumulator as
  physics/animation) — deterministic, replayable, and what the baseline
  tests rely on. Perception can tick at a lower rate (every N fixed
  ticks) if profiling asks; not built until then.

## Design
Per fixed tick, per agent (sandbox glue system):

```
perception: vision cone + injected LOS raycast -> blackboard (player_visible,
    last_known_pos)
behavior tree tick (blackboard) -> active leaf action
    action "path_to(target)": (re)query A* if target cell changed -> waypoints
    action "follow_path": steering arrive at next corner + separation
        -> desired velocity -> capsule body (same feed as player input)
anim glue: capsule speed -> Phase 6 state machine (walk/run), as the player does
```

Bake, at level load: static boxes → `bake_navgrid` → shared by all agents.

## Milestones
1. **A* core.** Grid struct + A* + binary heap + octile heuristic; unit
   tests for optimality on hand-built grids (see test plan).
2. **Navgrid bake + smoothing.** Box rasterization with radius inflation,
   invariants tests; supercover line-of-walkability + path smoothing.
3. **Steering + path following.** Seek/arrive/separation; a sandbox agent
   capsule follows a clicked/waypointed path around the ground-box
   obstacles; debug-draw of grid + path (renderer line support or colored
   quads — whatever Phase 12 debug-draw state exists by then; a thin
   stopgap is acceptable).
4. **Behavior tree + blackboard.** Node types, tick semantics, blackboard;
   tick-order and resume unit tests; patrol behavior in the sandbox.
5. **Perception + demo + sign-off.** `ge_physics` raycast query
   (ray-vs-broadphase + ray-vs-box/sphere/capsule, tested in the physics
   suite); vision cone + LOS; the full patrol→spot→chase→lose loop against
   the player; manual review; phase DoD sign-off.

## Test plan
Per plan.md's Phase 9 critical-test line:
- **Unit (A* optimality):** on hand-built grids with known shortest paths
  — straight line, single wall detour, spiral, no-path (returns failure),
  start==goal; path cost equals the hand-computed optimum (octile), not
  just *a* path.
- **Unit (navgrid invariants):** every cell inside an inflated box
  footprint is blocked and every cell outside is walkable (sampled
  exhaustively on small grids); rotated boxes; bake determinism (same
  input → identical bitmask).
- **Unit (smoothing):** smoothed paths never cross a blocked cell
  (supercover check re-applied as the assertion) and are never longer
  than the raw path.
- **Unit (BT tick order):** an instrumented tree logs visit order —
  Sequence short-circuits on Failure, Selector on Success; a Running
  child is resumed without re-ticking earlier siblings; state resets on
  completion.
- **Unit (perception):** stub raycast — in-cone + clear LOS ⇒ visible;
  in-cone + blocked ⇒ not; behind ⇒ not (never calls the raycast);
  exactly-on-cone-edge boundary case.
- **Unit (physics, Milestone 5):** raycast hits/misses against
  box/sphere/capsule at hand-computed distances + normals, in the
  `ge_physics` suite.
- **Baseline:** a seeded agent path-following run ends within tolerance of
  the goal in a recorded number of ticks (deterministic, fixed step —
  same tier as the Phase 5/6 baselines, in `sandbox_tests` since it links
  ai + physics glue).
- **Manual:** chase behavior feel/review — recorded sign-off.
